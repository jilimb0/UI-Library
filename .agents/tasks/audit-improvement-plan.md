## 2. Блокеры релиза и безопасность (P0)

### 1. [P0] Отсутствие Rate Limiting на публичных и вычислительно тяжелых эндпоинтах
- **Целевой модуль:** `security_qa` (Вектор: `security_qa`, Приоритет: **P0**, ICE Score: 560)
- **В чем проблема:** В кодовой базе не обнаружено middleware ограничения частоты запросов (Rate Limiter).
- **Влияние на бизнес и пользователей:** Брутфорс авторизации, парсинг API или спам запросами к LLM/БД приведут к исчерпанию квот и перерасходу бюджета.

#### 💡 Продуктовое решение:
Защитить публичные эндпоинты и ресурсоемкие операции (генерация, экспорт, вызовы LLM) лимитами запросов (Rate Limiting), предотвращая DoS и перерасход бюджета API.

#### ✅ Критерии приемки (Acceptance Criteria):
- [ ] Для публичных API эндпоинтов включен Sliding Window Rate Limiter (например, 60 запросов в минуту на IP).
- [ ] Для тяжелых и AI-операций действует лимит не более 5-10 запросов в минуту с понятным ответом `429 Too Many Requests` и заголовком `Retry-After`.
- [ ] Легитимные пользователи не получают ложных блокировок при стандартных сценариях работы.

#### 🛠 Рекомендуемый патч / изменения в коде:
```diff
--- a/src/index.ts
+++ b/src/index.ts
@@ -1,1 +1,2 @@
+// [GAVEL AUTO-REMEDIATION: sec-no-rate-limit] Подключить Sliding Window Rate Limiter по IP и userId (60 req/min для API и 5 req/min для auth/AI эндпоинтов).
```

### 6. [P2] Отсутствует контейнеризация (Dockerfile / docker-compose)
- **Целевой модуль:** `infra_devops_ai` (Вектор: `infra_devops_ai`, Приоритет: **P2**, ICE Score: 450)
- **В чем проблема:** В корне проекта не найдены Dockerfile или декларации оркестрации контейнеров.
- **Влияние на бизнес и пользователей:** Дрейф окружений и высокое время восстановления (RTO) при переносе сервиса на новый сервер.

#### 💡 Продуктовое решение:
Создать легковесный production-grade Dockerfile с multi-stage сборкой и непривилегированным пользователем для стабильного деплоя в любом облаке.

#### ✅ Критерии приемки (Acceptance Criteria):
- [ ] Создан `Dockerfile` с multi-stage билдом, минимизирующим финальный образ.
- [ ] Контейнер запускается под непривилегированным пользователем (`USER node`), настроен `HEALTHCHECK`.
- [ ] Образ успешно собирается и стартует сервис локально за время менее 60 секунд.

#### 🛠 Рекомендуемый патч / изменения в коде:
```diff
--- /dev/null
+++ b/Dockerfile
@@ -0,0 +1,10 @@
+FROM node:22-alpine AS base
+WORKDIR /app
+COPY package*.json ./
+RUN npm ci --omit=dev
+COPY . .
+USER node
+EXPOSE 3000
+HEALTHCHECK --interval=30s --timeout=5s CMD wget -qO- http://localhost:3000/health || exit 1
+CMD ["node", "dist/index.js"]
```
