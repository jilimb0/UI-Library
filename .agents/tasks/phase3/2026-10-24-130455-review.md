# Ф3: Component-state tokens consumed by components

Component-state token groups for eight new components (`checkbox`, `radio`, `slider`, `tabs`, `accordion`, `pagination`, `tooltip`, `dropdown`) have been added to `tokens.w3c.json`, artifacts rebuilt, `components.css` migrated to `--ucl-*` state tokens, and `ButtonSize` aligned to `'sm' | 'md' | 'lg' | 'icon'` in both packages. All `opacity: 0.9` hover hacks are gone, replaced by proper state tokens or `filter: brightness()`. Watch for: the outline button's `border-color` on both the base rule and the hover rule still use raw `var(--input)` / `var(--border)` rather than the `--ucl-input-border-*` tokens called for in the plan.

**Verdict**: CHANGES_REQUESTED

## High-level view

The token pipeline is correctly extended: all eight new component groups appear in both `color.component.light` and `color.component.dark`, and `dist/w3c/tokens.css` reflects the expanded output. The `--ucl-*` token consumption across `components.css` is thorough — every call includes a semantic fallback, so components degrade gracefully when `ThemeProvider` is absent.

`ButtonSize` now reads `'sm' | 'md' | 'lg' | 'icon'` in both `packages/behaviors/src/button.ts` and `packages/core/src/types/component-types.ts`. The `createButtonBehavior` guard is correctly updated from `size !== 'default'` to `size !== 'md'`, and `.ucl-button--md` exists in `components.css`.

The one deviation from the Ф3 plan is in the outline button: the plan required wrapping `border-color` in `--ucl-input-border-default` (base) and `--ucl-input-border-hover` (hover) — the tokens exist and are used correctly for `<input>` itself, but the outline button's rules still carry the raw references. This is a narrow miss, not a structural problem.

### Outline button border-color skipped tokenization

The plan specifies (§3, "AFTER" for `--outline`):

```css
border-color: var(--ucl-input-border-default, var(--input));
/* hover */
border-color: var(--ucl-input-border-hover, var(--border));
```

What shipped:

```css
/* line 146 */
border-color: var(--input);

/* line 152 (hover) */
border-color: var(--border);
```

The tokens `--ucl-input-border-default` and `--ucl-input-border-hover` both exist in `tokens.w3c.json` and are already consumed by `<input>` at lines 260 and 316 of `components.css`. This is a confirmed omission — `grep -n 'border-color.*var(--input)' components.css` returns only line 146.

Because the outline button's border is its primary visual differentiator, this is the one place where the absence of a token fallback is most visible when `ThemeProvider` supplies a custom outline border color at the component level.
